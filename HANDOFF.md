## 1. Что за проект

Владелец делает мини-приложения (Telegram Mini Apps) для малого бизнеса в РФ под заказ.
Этот проект — его **собственная витрина**: мини-приложение в Telegram, которое он показывает потенциальным клиентам.
Клиент открывает бота → видит живые демо → нажимает «Обсудить проект» → попадает в личный чат с владельцем.

**Принятые решения (не пересматривать без владельца):**
- Сейчас нужна **простая показательная демка**: без сервера, без базы данных, без сбора и хранения контактов.
- Два файла (`prototype/index.html` + `prototype/data.js`) → GitHub Pages → кнопка меню бота @Bustool_bot (настроена через Bot API). Демо: https://alexandrkom85-beep.github.io/mini-up-teleka/prototype/
- GitHub Pages с российских IP открывается нестабильно (17.10.2026: `ERR_CONNECTION_CLOSED`). С 19.10.2026 витрина в **Yandex Object Storage**: https://bustool-showcase.website.yandexcloud.net/ — кнопка бота ведёт сюда.
  - Облако `cloud-alexandr-komar`, каталог `default`, бакет `bustool-showcase` (публичное чтение, хостинг сайта).
  - Публикация: `bash publish.sh` (сервисный аккаунт `showcase-publisher`, роль `storage.editor`; ключ — `.env` → `YC_SA_KEY_JSON`). Утилита yc: `~/yandex-cloud/bin/yc`, профили `showcase` (вход владельца через браузер, ~12 ч) и `showcase-sa`.
  - Вход владельца в yc: с 01.06.2026 OAuth-токены Яндекса для yc не принимаются — только `yc init` с входом через браузер.
- Кнопка «Обсудить проект» открывает чат с владельцем в Telegram (через `Telegram.WebApp.openTelegramLink`). Контакты нигде не сохраняются.
- **Админка** (с 19.10.2026, схема — `docs/07-admin-architecture.md`): пункт «Админка» на главной виден только владельцу. Витрина отправляет `initData` Telegram в Cloud Function `showcase-admin`; функция проверяет подпись токеном бота и сравнивает user.id с `OWNER_TELEGRAM_ID`, сохраняет `data.json` в бакет, перед этим кладёт копию в `backup/`. Правится: цены, тексты экранов, «закончилось/скрыть», порядок плиток, чипов и пунктов «Что получает бизнес».
- Живые данные — `data.json` в бакете. `prototype/data.js` — исходник: `bash publish.sh --data` заменит живые данные на него (старые уйдут в backup). Локально (file://) витрина берёт data.js.
- Формы в демо ничего не сохраняют и не отправляют, localStorage не используется.
- Сервер, база, хранение заявок, 152-ФЗ, обход ограничений Telegram API — **только когда появится реальный клиентский проект**.
- Четыре демо: **ремонт/отделка** (калькулятор → заявка на замер; у владельца опыт в строительстве), **доставка обедов** (меню дня → корзина → время доставки, стиль @DurgerKingBot), **посуточная аренда** (квартиры → календарь → бронь), **дома и бани под ключ** (каталог проектов → комплектация и доп. работы → цена и срок → заявка на смету; добавлено 17.10.2026 вместо плитки админки).
- Стиль (с 17.10.2026, по референсу `design/refs/01-stars-trade-hub.png`) — тёмный «премиум»: всегда тёмная тема, плитки с градиентным свечением и 3D-значками Fluent Emoji (единый стиль на всех телефонах, с 19.10.2026), ряд чипов, синяя главная кнопка `#2F6BFF`, без нижнего меню. Шапка и MainButton — настоящие телеграмовские.

## 3. Как устроена витрина

- Без сборки и зависимостей. `index.html` открывается двойным кликом в браузере и сам подключает `data.js` из той же папки.
- `data.js` — объект `window.SHOWCASE`: ник для чата, тексты главной, виды работ и цены ремонта, меню и цены обедов, квартиры и цены аренды, проекты/комплектации/доп. работы стройки, тексты экрана «Готово». Логики там нет. Если в `data.js` опечатка, вместо витрины показывается сообщение «Ошибка в data.js».
- `index.html` подключает `https://telegram.org/js/telegram-web-app.js`. Внутри Telegram прячет нарисованные шапку и кнопку, использует настоящие `MainButton` / `BackButton`, красит шапку и фон в `#0B0D12`.
- `scr.*` — экраны: `home`, `repair`, `repairForm`, `lunch`, `lunchForm`, `rent`, `flat`, `flatForm`, `build`, `house`, `buildForm`, `done`. Каждый возвращает `{title, sub, html, main}`; `main` — главная кнопка.
- Площадь в ремонте: ползунок, ввод числом или «длина × ширина» — синхронно; можно больше максимума ползунка (до 1000 м²).
- Все цены в демо примерные (помечено в интерфейсе).
- Проверено 17.10.2026 (Playwright + Chrome, 390px), 33 проверки: все четыре сценария до экрана «Готово», расчёты цен, правки в `data.js` видны на экранах, опечатка даёт понятное сообщение, localStorage пуст, ошибок в консоли нет.

## 5. Что дальше — по шагам

Шаги 1–3 выполнены (бот, GitHub, публикация). Актуальны шаги 4–5.

### Шаг 1. Подготовка (делает владелец)
1. **Бот:** в Telegram @BotFather → `/newbot` → название → юзернейм на `bot`. Токен вставить в `.env` после `BOT_TOKEN=`. В чат токен не присылать.
2. **Ник** в Telegram — вставить в `CONTACT` в `prototype/index.html`.
3. **Решить про iCloud:** рекомендуется перенести папку в `~/Projects/mini-up-teleka` (iCloud может выгружать файлы и конфликтовать с папкой `.git`). Копия всё равно будет на GitHub.
4. **GitHub:** зарегистрироваться на github.com.

### Шаг 2. Git и GitHub
Вариант через VS Code (без терминала):
1. VS Code → File → Open Folder → `mini-up-teleka`.
2. Слева значок **Source Control** → **Initialize Repository**.
3. Проверить, что `.env` НЕ попал в список файлов (его исключает `.gitignore`).
4. Ввести сообщение «Первая версия витрины» → **Commit**.
5. **Publish Branch / Publish to GitHub** → войти в GitHub → выбрать **Public** (бесплатный GitHub Pages работает с публичными репозиториями; секретов в репозитории нет).

### Шаг 3. Публикация демки
1. На github.com открыть репозиторий → **Settings → Pages** → Source: Deploy from a branch → Branch `main`, папка `/ (root)` → Save.
2. Ссылка будет вида `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/prototype/` (файл лежит в папке `prototype`). Либо перенести `index.html` в корень репозитория, тогда ссылка короче.
3. Открыть ссылку **на телефоне без VPN**. В мае 2026 у GitHub в РФ были сбои; если не открывается — переносим на российский хостинг (например, Yandex Object Storage).
4. @BotFather → `/setmenubutton` → выбрать бота → вставить ссылку → назвать кнопку (например «Открыть витрину»).
5. Проверить в Telegram: все 3 демо, админка, светлая/тёмная тема, кнопка «Обсудить проект» открывает чат.

### Шаг 4. Доводка демки
Владелец проходит все экраны и составляет список «добавить / убрать / поменять». Правки вносятся по одной, после каждой — проверка всех экранов и коммит с понятным названием.

### Шаг 5. Упаковка и проверка спроса
- Описание и аватар бота, текст рекламного поста, скриншоты.
- Ориентир (предложение, не факт): отправить ссылку 20 владельцам бизнеса, ежедневно считать: отправлено → ответили → нажали «Обсудить проект» → созвоны.
