# Этап VII (часть). Хостинг в России и админка витрины

Статус: **согласовано владельцем 19.10.2026, реализовано.** Функция: `admin/function/index.js`, деплой `bash admin/deploy-function.sh`, экран — `scr.admin` в `prototype/index.html`.

## Зачем
1. GitHub Pages с российских IP открывается нестабильно (ошибка `ERR_CONNECTION_CLOSED`, медленная загрузка, проверено владельцем 17.10.2026).
2. Владелец хочет менять цены, тексты и порядок плиток прямо в мини-приложении, и чтобы вход был только у него.

## Схема

```
Telegram / браузер
      │  открывает витрину
      ▼
Yandex Object Storage (бакет-сайт)
   index.html · data.json · icons/
      ▲                       ▲
      │ читает data.json      │ записывает data.json
      │                       │
   все посетители        Cloud Function «save»
                             ▲  1) проверяет подпись Telegram (initData) токеном бота
                             │  2) пускает только OWNER_TELEGRAM_ID из .env
                             │
                     экран «Админка» в витрине
                     (виден только владельцу)
```

## Как работает вход
- Telegram сам передаёт в мини-приложение подписанные данные пользователя (`initData`). Подпись сделана токеном бота; подделать её без токена нельзя.
- Функция на сервере проверяет подпись и сравнивает **Telegram ID** (число) с `OWNER_TELEGRAM_ID`. По нику не сверяем: ник можно сменить, а освободившийся ник может занять другой человек.
- Токен бота хранится только в настройках функции (секрет), не в коде витрины и не в репозитории.
- Проверка на телефоне — только чтобы спрятать кнопку «Админка» от остальных; защита — на сервере.

## Что можно менять в админке (MVP)
- цены: работы ремонта, блюда, квартиры, комплектации и допработы стройки;
- тексты заголовков и подписей;
- «закончилось» у блюд, «скрыть» у квартир и проектов;
- порядок плиток и чипов на главной (стрелки вверх/вниз).

Не входит в MVP: загрузка фото, история изменений, несколько администраторов, заявки клиентов.

## Данные
- `data.js` превращается в `data.json` в бакете. Перед каждой записью функция сохраняет копию `backup/data-<дата>.json` — можно откатить ошибку.
- `data.json` в Git остаётся «исходником»; правка через VS Code тоже продолжит работать.

## Стоимость (факты и оценки)
- Cloud Functions: 1 000 000 вызовов в месяц бесплатно ([Yandex Cloud, Free tier](https://yandex.cloud/ru-kz/all-offers)). Админка делает единицы вызовов в день.
- Object Storage: плата за хранение, операции и трафик ([документация](https://yandex.cloud/ru/docs/storage/concepts/hosting)). Сайт ~1 МБ — ожидаем рубли в месяц; **точную цифру проверить по тарифам перед запуском** (не проверено).

## Шаги
1. Владелец: `yc init` (вход в Yandex Cloud из терминала).
2. Перенос витрины в Object Storage, новая ссылка в кнопку бота. **(не зависит от админки)**
3. После согласования схемы: функция `save`, экран «Админка», перенос данных в `data.json`.
4. Проверки: вход с аккаунта владельца — пускает; с другого аккаунта и из браузера без Telegram — не пускает; правка видна посетителям.
