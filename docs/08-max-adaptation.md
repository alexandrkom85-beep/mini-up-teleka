# Адаптация витрины под MAX — исследование и план

Составлено 20.10.2026. Статус: **на согласовании**, код не менялся.

Решение: **одно приложение на обе площадки** (тот же `index.html`, те же данные и админка). Витрина сама определяет, где открыта.

## 1. Что известно о MAX (факты, с источником)

Источники: [dev.max.ru/docs/webapps/bridge](https://dev.max.ru/docs/webapps/bridge), [validation](https://dev.max.ru/docs/webapps/validation), [introduction](https://dev.max.ru/docs/webapps/introduction), [создание бота](https://dev.max.ru/docs/chatbots/bots-create/create), [подключение организации](https://dev.max.ru/docs/maxbusiness/connection), официальный справочник [max-agents-skill/mini-apps-bridge.md](https://github.com/max-messenger/max-agents-skill/blob/main/references/mini-apps-bridge.md) (сверен 21.09.2026), сам скрипт `st.max.ru/js/max-web-app.js` (скачан 20.10.2026).

**Подключение и доступ**
- Мини-приложение живёт только внутри бота MAX. Отдельной регистрации нет: business.max.ru/self → Чат-боты → бот → ⋮ → Настройки → вставить ссылку → выбрать кнопку (Открыть / Старт / Играть / без подписи).
- Бот создают ООО, ИП **и самозанятые** (резиденты РФ). Подтверждение — через Госуслуги (ООО/ИП ещё через Т-Бизнес ID, Альфа ID). Ботов: ООО/ИП — до 5, самозанятый — до 2.
- Ник бота выбрать нельзя: `idИНН_bot` (ООО/ИП) или `se<номер>_bot` (самозанятый). Ссылка: `max.ru/<ник>`.
- После создания бот проходит модерацию — до 48 ч в рабочие дни. Токен и привязка мини-приложения доступны только после модерации.
- Карточка бота: логотип 500×500 (jpg/png, до 5 МБ), название до 59 символов без эмодзи, описание до 200 символов.
- Ссылка на мини-приложение: только https, до 1024 символов, буквы латиницы, цифры, точки, дефисы. Хостинг любой → наш бакет Yandex подходит.
- Открыть мини-приложение ссылкой: `https://max.ru/<ник_бота>?startapp=<код>` (код — латиница, цифры, `_`, `-`, до 512).

**Что есть в MAX Bridge (`window.WebApp`, скрипт `https://st.max.ru/js/max-web-app.js`)**
- `initData` (строка для проверки на сервере), `initDataUnsafe` (user.id, first_name, username…, `start_param`), `platform`: ios / android / desktop / web.
- `BackButton` (show / hide / onClick) — как в Telegram.
- `HapticFeedback` — те же названия, что в Telegram (не работает на компьютере и в вебе).
- `openLink(url)` — внешний браузер; `openMaxLink(url)` — ссылка `max.ru/...` внутри MAX.
- `ready()`, `close()`, `enableClosingConfirmation()`, вертикальные свайпы вкл/выкл.
- Скрипт сам сохраняет initData в sessionStorage (это делает MAX, не мы).

**Чего в MAX нет (важно для нас)**
- **Нет главной кнопки** (`MainButton`) — рисуем свою синюю кнопку внизу (она уже есть для браузера).
- **Нет цветов шапки/фона** (`setHeaderColor`, `setBackgroundColor`) и темы — шапку красит MAX, наш тёмный фон остаётся.
- **Нет `expand`, `showConfirm`** — подтверждение удаления в админке через обычное `confirm()`.
- **Нет документированной ссылки на личный профиль пользователя** — см. открытые вопросы.

**Проверка подписи (админка)**
- Алгоритм тот же, что в Telegram: ключ = HMAC-SHA256("WebAppData", токен бота), подпись по отсортированным `key=value` через `\n`, сравнить с `hash`. Разница — **другой токен** (бота MAX) и другой ID владельца.

## 2. Что меняем

| Где | Telegram сейчас | MAX |
|---|---|---|
| Определение площадки | `Telegram.WebApp.initData` | в адресе после `#` есть `WebAppData` → подгружаем скрипт MAX; в Telegram — `tgWebAppData` |
| Главная кнопка | `MainButton` Telegram | своя кнопка внизу (как в браузере) |
| Шапка | настоящая Telegram, наша спрятана | шапка MAX; нашу «‹ Назад» прячем, используем `BackButton` MAX — **проверить на телефоне**, как выглядит |
| Цвета | `setHeaderColor/BackgroundColor` | не вызываем |
| Вибро-отклик | `TG.HapticFeedback` | `WebApp.HapticFeedback` — одна общая обёртка |
| «Обсудить проект» | `openTelegramLink(t.me/ник)` | `openMaxLink(<ваша ссылка в MAX>)` — ссылка в `data.js`, поле `contactMax` |
| Подтверждение удаления (админка) | `showConfirm` | `confirm()` |
| Тексты | «Уведомление в Telegram», ссылки офисов `t.me/...` | «Уведомление в MAX», `max.ru/бот_столовой?startapp=...` |
| Админка (Cloud Function) | проверка токеном Telegram, `OWNER_ID` | витрина передаёт `platform: 'max'`; функция проверяет токеном `MAX_BOT_TOKEN`, сравнивает с `OWNER_MAX_ID` |

Код делается одной обёрткой `P` (площадка): `P.name`, `P.main(text)`, `P.back(show)`, `P.haptic(...)`, `P.openChat()`, `P.confirm(...)`, `P.initData`. Экраны не меняются.

Адрес — тот же `https://bustool-showcase.website.yandexcloud.net/`: площадку различаем по адресу после `#`, отдельная папка не нужна.

## 3. План по шагам

1. **Владелец:** профиль на business.max.ru (ООО или самозанятость) → подтверждение через Госуслуги → создать бота (логотип, название, описание) → ждать модерацию (до 48 ч).
2. **Claude (параллельно, без публикации):** обёртка площадки в `index.html`, поле `contactMax` в `data.js`, тексты «Telegram/MAX» по площадке, проверка подписи MAX в функции админки. Проверка в браузере: Telegram-версия не сломалась.
3. **Владелец после модерации:** токен бота MAX → в `.env` (`MAX_BOT_TOKEN`), привязать ссылку витрины в настройках бота, кнопка «Открыть».
4. **Проверка на телефоне в MAX:** шапка и «Назад», своя кнопка внизу, отступы, вибро, «Обсудить проект», админка. Узнать ваш ID в MAX (витрина покажет его один раз) → `OWNER_MAX_ID` в `.env`.
5. **Публикация** (с подтверждения): `bash admin/deploy-function.sh`, `bash publish.sh` (без `--data`).
6. Обновить HANDOFF, CLAUDE.md.

## 4. Открытые вопросы (проверить, не предполагать)

1. **Куда ведёт «Обсудить проект» в MAX.** Ссылки на личный профиль в документации нет. Варианты: (а) ссылка на ваш профиль из MAX («Поделиться контактом/профилем» — проверить, даёт ли MAX ссылку `max.ru/...`); (б) ваш бот MAX (ответы в боте без сервера не получить — не подходит); (в) открыть ваш Telegram через `openLink` (уводит из MAX — запасной вариант).
2. **Шапка MAX:** есть ли в ней своё название и «Назад», не дублируется ли с нашей — смотреть на телефоне.
3. **`auth_date` в MAX** — в секундах (по справочнику) или миллисекундах: проверить на реальных данных, от этого зависит проверка «подпись не старше суток».
4. **Модерация бота:** требования к содержанию — [dev.max.ru/docs/legal/requirements](https://dev.max.ru/docs/legal/requirements); демо-формы ничего не собирают — риск низкий (гипотеза).
5. **Ник бота с ИНН** (`idИНН_bot`) виден клиентам. У самозанятого — `se..._bot`. Выбор профиля — за владельцем.
